# Demo script

Both scripts describe the current build: the Cabins page (`/`) is the home page and the default for everyone; the full workspace is the Explorer (`/explore`). Numbers are computed by `docs/_gen/build.py` from the analysis API.
Numbers marked "at dataset 4fe55f76142a" were read off the running app and will change if the dataset or model is rebuilt; re-check them before presenting.

Setup (one time, from the repository root):

```bash
cd services/analysis && uv run blindspots serve      # API on http://127.0.0.1:8000
cd apps/web && npm run dev                           # open http://localhost:3000
```

For the static deployment use `NEXT_PUBLIC_DATA_MODE=snapshot` (see README). In snapshot mode everything below works for documented cabin atmospheres, but custom targets, arbitrary candidates and arbitrary slice values show a "requires the live analysis service" state.

## A. 30-second tour (the built-in "30-second tour" does this automatically)

Press the quiet **30-second tour** button under the title on the Cabins page, or open `/?demo=1`. The tour autoplays on the real page for about 29 seconds: a 2.5 s title card, five scenes and a 3.5 s end card (Space pauses, the arrow keys step, Esc exits; with reduced motion it does not autoplay, so step with Next). Each scene scrolls to one section, rings it, and shows one short caption of at most 14 words, at most three facts and, where it applies, the mandatory small print. Every number comes from the API. Suggested narration, one sentence per scene:

0. **Title card.** "Do NASA's space-station fire tests cover this cabin's air?"
1. **"ISS flame tests cover the station's own air."** The ISS card is ringed. The one fact shown is the count of nearby ISS test results: 241 (dataset 4fe55f76142a). If the ISS card ever read "Barely covered" or "Not covered", the caption changes to say so.
2. **"Now pick a Moon or Mars cabin: NASA's Exploration Atmosphere."** The card shows 34 % oxygen, 56.5 kPa and the coverage chip. It reads "Not covered" because there are 0 nearby ISS test results in any of the 20 material setups.
3. **The answer (two beats).** First the verdict line: "Blind spot: no ISS test in our data ran in air like this." (for Thin PMMA films · opposed flow the API verdict is "insufficient evidence"; no probability is shown when nothing is supported.) The facts under it are the count of nearby ISS test results, this cabin's air and the pressure the ISS tests ran at, labelled "assumed, not recorded" when the dataset assumed it (BASS-II did not record pressure). Then the chart: oxygen against pressure, NASA test results as dots (filled = flame kept burning, hollow = went out), the shaded "Where ISS tests ran" area and the bold "This cabin" marker far from it. 0 of 9 sampled conditions of this cabin have a nearby test result; the nearest is 8.3 reference distances away.
4. **"Machine learning ranks the most informative next experiment."** Top pick: 34.0 % oxygen, 56.5 kPa, airflow 1.71 cm/s; it would cut the model's uncertainty about this cabin by 19.3%. It is a computational research candidate that requires qualified scientific review; the mandatory framing sentence is shown in small print. The top-ranked candidate sits at the target conditions themselves; this follows from the model's distance-based (stationary) correlation assumption, because no integrated observation constrains that region.
5. **"Either outcome would cut uncertainty by ..."** (the scene is "What would we learn?"). Two short lines give the change in uncertainty if the flame keeps burning and if it goes out, under the line "Hypothetical model updates, not experimental results."
6. **End card.** "Blind Spots. Where NASA's ISS fire-test records end, and what to learn next."

## B. 3-minute technical demo

Everything here is clickable in the current UI. Keep the framing: a research-planning tool, not a fire-safety certification, not endorsed by NASA. The product is three steps on one page, then expert views behind them.

**0:00 - The idea and Step 1, pick a cabin (30 s).** Open **Cabins**. Read the title and the one-sentence subtitle: NASA burned materials aboard the ISS to learn when flames keep burning; the air planned for Moon and Mars cabins (thinner, more oxygen) is missing from those records. Point at the cabin cards ("Today and next", "Past spacecraft"): each shows the air (for example 21 % oxygen, 101 kPa) and a chip, **Covered**, **Barely covered** or **Not covered**, with the count of nearby ISS test results (hover the chip for the definition of "nearby"). The ISS card has 241; 8 of the 11 documented cabin atmospheres have none, including all 7 below 1 atm (Shuttle pre-EVA, Exploration Atmosphere, Artemis Surface Habitat, EAWG 2006, Orion lunar, Skylab, Apollo).

**0:30 - Step 2, the answer (40 s).** The page opens on the NASA Exploration Atmosphere (the selection lives in the URL as `?cabin=`). Read the coloured verdict (never colour alone: icon plus words); a chip beside the cabin name says what kind of cabin it is (for the Exploration Atmosphere: a NASA design recommendation, not a built or approved cabin). The **Material** picker sits right under the verdict. Then the chart: oxygen (%) against cabin pressure (kPa); dots are NASA test results for the chosen material, the shaded area is "Where ISS tests ran", "This cabin" is the bold marker, other cabins are small faint labels. All ISS tests sit at about 1 atm, so the cabin is far outside them. In the picker each option shows its count of nearby test results; the default is the data-driven Thin PMMA films · opposed flow. Under the chart, "By material" says how many of the 20 material setups have nearby tests for this cabin (0 for the Exploration Atmosphere). Say plainly: NASA ground tests with a documented range that includes this air exist, the model does not use them, and the Explorer lists them (documented range is not the same as a test at these exact conditions). "Show as table" gives the same chart as text. If asked about gravity: every ISS test ran in microgravity and NASA's PSI holds no partial-gravity combustion data, so "covered" is about the air only.

**1:10 - Step 3, what to test next (35 s).** Read the small-print framing sentence first (computational research candidates requiring qualified scientific review), then the line that gives the closest ISS test of this material and how far it is from the cabin's air (the size of the gap). Read the top three research candidates for this cabin and material, each as one sentence with three facts (oxygen and pressure, airflow, expected reduction of the model's uncertainty). The top candidate is 34.0 % oxygen, 56.5 kPa, 1.71 cm/s, with an expected reduction of the model's uncertainty of 19.3%; the baselines' picks, scored with the same model: random 0.0%, uncertainty sampling 0.0%, nearest gap 15.8%. The top-ranked candidate sits at the target conditions themselves; this follows from the model's distance-based (stationary) correlation assumption, because no integrated observation constrains that region. Then **What would we learn?**: the two hypothetical outcomes for candidate 1, labelled hypothetical model updates, not experimental results. Candidates are computational and need qualified review. If a material has too few test results to rank, the page says so in one calm sentence and suggests another material.

**1:45 - Explorer, the expert workspace (40 s).** Press **Open this cabin in the Explorer**: `/explore?target=<cabin>&group=<material>` (any old `/?group=...` link redirects there). Choose a material, then use **Show** to switch the layers: Test results, Prediction, Uncertainty, Coverage, Related NASA work. Switch the chart between oxygen against airflow and oxygen against pressure and move the slice. Read the target panel: number of nearby test results, nearest distance, the verdict with reasons, the airflow band and its source (for profiles without their own band: the documented ventilation band with a near-quiescent extension, labelled as an analysis choice), and the NASA investigations for this cabin that are not integrated. The candidate panel offers **Compare** for two candidates (it can answer "indistinguishable"), the sensitivity of the ranking to the assumed pressure correlation (0.15 / 0.3 / 0.6) and the counterfactual with "Show on map".

**2:25 - Provenance and honesty (30 s).** Open **Experiments** (276 experiments): filter, open any row to see the quoted source token, its row and column and the flagged assumptions (for example BASS-II pressure is "not recorded in the source"; an assumed value is shown separately). Then **How it works**: data (250 integrated ISS experiments, 565 training observations, 78% sustained, 26 further experiments as context only), the model, validation and limits. Say plainly: the model beats the majority-class baseline (95 % CI excludes 0) in 6 of 9 modelled groups, in 0 of those mostly because flow-off steps are easy negatives; pressure is assumption-driven (fixed length scale 0.3); the retrospective check is modest: the ranking beat random in 11 of 18 scenarios.

**3:00 - Close.** Reproducible: `build-dataset`, `train`, `retrospective`, `export-artifacts` regenerate the data, model and static snapshot deterministically; limitations are listed in the app and in `docs/limitations.md`. The **Research brief** (`/brief`) is a printable seven-section summary for a chosen cabin.

Things that are **not** in the demo because they are not implemented: a 3D view, user accounts or saved sessions, per-test spread-rate predictions, and any claim about conditions covered only by non-integrated investigations.
Custom targets exist only with the live service.
