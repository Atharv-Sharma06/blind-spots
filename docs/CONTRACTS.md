# Blind Spots: build contracts (source of truth for every contributor)

Blind Spots maps where NASA microgravity solid-fuel combustion experiments have and have not
established evidence, trains an uncertainty-aware model on compatible observations, and ranks
computational research candidates by expected information about a selected cabin atmosphere.

Read this file before writing code. If something you need is not specified, choose the most
conservative option and record it in `docs/decisions.md` (append, never rewrite others' entries).

---

## 0. Integrity rules (non-negotiable)

1. Never fabricate measurements, outcomes, citations, URLs, DOIs or quotes. Every number shown in the
   product must come from (a) a cited source file/document, or (b) a documented computation on such data.
2. Synthetic data is allowed **only inside unit tests** (under `services/analysis/tests/` or
   `apps/web/tests/`), clearly named `synthetic_*`/`fixture_*`, and must never be imported by app code.
3. Missing values stay missing (`null`). Documented assumptions are stored in separate, explicitly named
   fields (e.g. `pressure_assumed_kpa`) with a quality flag, never written into a measurement field.
4. No operational combustion-test instructions, ignition procedures or apparatus procedures anywhere.
   Candidates are "computational research candidates requiring qualified scientific review, established
   safety procedures and formal feasibility assessment".
5. No claim of NASA approval/endorsement; no claim of certified fire-safety assessment.
6. Do not claim NASA has "not studied" a condition. Say "not represented in the integrated records".
7. Do not include `PSI-26_Science Documents_Planned_Test Matrix.xlsx` anywhere (its header cell contains
   what look like legacy credentials). It is not needed.
8. Browser tests run **headless only**. Never open visible browser windows on this machine.
9. Do not run state-changing git commands (commit, checkout, reset, stash, rebase, push). The lead commits.
10. Stay inside the files/directories your task owns (section 1). Read anything; write only what you own.

## 2. Curation tables (interpretation of free-text source cells)

The BASS/BASS-II matrices record flow schedules and outcomes as free text. Interpretation is captured in
CSV tables with exact provenance. The pipeline re-reads the original `.xlsx`, and **verifies that every
`raw_token` is an exact substring of the cited cell** (`source_row` + `raw_column`). Rows that fail are
flagged `provenance_mismatch` and excluded from training.

Investigation IDs: `PSI-25` = BASS-II (2014–2016 ISS/MSG), `PSI-26` = BASS (2012–2013 ISS/MSG).
Test labels: BASS-II uses the "Test no." cell verbatim (e.g. `O15b`); BASS uses the "As run test no."
cell verbatim (e.g. `45`); when that cell is not a test number (SETUP, STOW, dilution test) the row is not a test.
BASS rows whose "As run test no." repeats (e.g. two rows labelled `85`) get suffixes from the "Test no."
column: label = `<as-run no.>/<test no.>` (e.g. `85/117`, `85/117a`) to stay unique.

### 2.1 `data/curation/tests/<chunk>.csv` (one row per test)

| column | meaning |
|---|---|
| investigation_id | `PSI-25` or `PSI-26` |
| test_label | as above |
| source_file | path relative to repo root |
| source_sheet | sheet name |
| source_row | Excel row number (1-based) |
| material_family | enum: `pmma_thin_film` (<1 mm sheet/film), `pmma_slab` (≥1 mm sheet/slab), `pmma_rod`, `pmma_sphere` (spheres and spherical sections), `sibal_fabric` (75/25 cotton/fiberglass), `nomex_fabric`, `ultem_sheet`, `wax_candle` (Japan wax or paraffin candles), `paraffin_slab`, `other` |
| specimen_geometry | enum: `flat_sheet`, `slab`, `rod`, `sphere`, `spherical_section`, `fabric_strip`, `candle` |
| thickness_mm | sheet/slab/film thickness in mm, else empty |
| diameter_mm | rod/sphere diameter in mm (inch values converted ×25.4), else empty |
| width_mm | sample width in mm if stated, else empty |
| sides_burning | `one`, `two`, or empty |
| pmma_color | `clear`, `black`, or empty |
| flame_configuration | enum: `opposed`, `concurrent`, `stagnation` (forward/upstream ignition of a bluff body), `wake` (wake ignition), `mixed`, `unknown` |
| configuration_evidence | short quote or source (e.g. "BASS-II ReadMe: ignite downstream end for opposed flow") |
| terminal_event | enum: `burnout`, `extinguished_low_flow`, `blowoff`, `self_extinguished`, `flow_turned_off`, `n2_suppressed`, `ignition_failed`, `brief_flame_only`, `test_aborted`, `unknown` |
| o2_anomaly | empty or short note when the O2 cells look like sensor glitches (e.g. final 0.6 or 39.1) |

### 2.2 `data/curation/steps/<chunk>.csv` (one row per flow step within a test)

| column | meaning |
|---|---|
| investigation_id, test_label, source_file, source_sheet, source_row | as above |
| step_index | 0-based order within the test |
| flow_value | number exactly as recorded (e.g. `5`, `0.36`, `62`); empty if no number |
| flow_unit | enum: `air_cm_s` (duct "Air display" reading or a value the source states in cm/s), `fan_display` (fan voltage×10 display, typically 38–122), `pot` (control-box pot setting 0–10), `none` |
| flow_qualifier | empty, `<` (source says "<1"), `~` (approximate), `max` (fan max) |
| flame_state | enum: `sustained` (flame persisted at this setting), `extinguished` (flame went out at this setting), `brief_flame_no_sustain` (flame appeared but did not sustain after the igniter stopped), `not_ignited` |
| extinction_mode | only when `extinguished`: `quench_low_flow`, `blowoff_high_flow`, `at_constant_flow`, `flow_turned_off`, `n2_suppression`; else empty |
| raw_token | exact substring of the source cell that supports this row (copy verbatim, including spacing) |
| raw_column | the column header text of that cell, normalized as in the dumps (e.g. `Fan display`, `Air display`, `Test Observations and Anomalies (ignited, spread, extinguished, burn time, color, etc.)`) |
| token_row | Excel row of the cell holding `raw_token` (usually = `source_row`; differs for BASS continuation rows) |
| confidence | `high` (explicit in source), `medium` (clear from context), `low` (interpretation) |
| note | free text |

Exact CSV headers (UTF-8, comma, minimal quoting, LF):
- tests: `investigation_id,test_label,source_file,source_sheet,source_row,material_family,specimen_geometry,thickness_mm,diameter_mm,width_mm,sides_burning,pmma_color,flame_configuration,configuration_evidence,terminal_event,o2_anomaly,confidence,note`
- steps: `investigation_id,test_label,source_file,source_sheet,source_row,step_index,flow_value,flow_unit,flow_qualifier,flame_state,extinction_mode,raw_token,raw_column,token_row,confidence,note`

Checker: `python scripts/check_curation_provenance.py <csv>...` (needs openpyxl) must report 0 errors.

Rules: record only what the source supports. Do not create a step for a flow whose flame state is
unknown. Do not convert units in the CSV (the pipeline converts). If the fan list and air list describe
the same steps, emit one row per physical step and choose the most direct flow evidence (`air_cm_s` if
the air reading is a steady numeric value; else `fan_display`/`pot`); mention the other in `note`.

### 2.3 Pipeline label rule (implemented in code, documented in methodology)
- `sustained` → label 1 (flame sustained).
- `extinguished` with mode in {quench_low_flow, blowoff_high_flow, at_constant_flow} → label 0.
- `extinguished` with mode `flow_turned_off` → label 0 at the recorded (near-zero) flow, flag `flow_off_transient`.
- `brief_flame_no_sustain` → label 0, flag `no_sustained_propagation`.
- `not_ignited`, `n2_suppression` → excluded from flammability training (reason recorded).
- Steps without a numeric flow, with `provenance_mismatch`, or with `confidence=low` **and** flag
  `below_calibration_range` remain in records; training inclusion is decided by the documented
  training filter, and sensitivity analyses report the effect of excluding low-confidence rows.

### 2.4 Flow conversion (implemented in code)
- `air_cm_s`: U = 1.0066 × AIR (note in `PSI-25_Reference Data_Fan calibration data.xlsx`: "U = 1.0066(AIR)").
- `fan_display` / `pot`: interpolate the fan-calibration table for the same restrictor count and the same
  GMT day when present; otherwise the nearest calibration day with that restrictor count; record
  `flow_calibration_ref`. Restrictor mapping: matrix "Flow restrictor" 0/1/2 ↔ calibration blocks
  "no restrictor"/"1 restrictor"/"2 restrictor" (verify against the sheet; document).
- Below the lowest calibrated non-zero point (pot < 0.5, fan display < ~42): linear extrapolation of the
  chosen day's curve through its two lowest non-zero calibration points, floored at 0 cm/s; flags
  `below_calibration_range` and `flow_extrapolated_linear`; uncertainty = ± max(0.5 cm/s, half the lowest
  calibrated flow). Why: the near-quench steps (pots 0.275–0.36) must keep their order; a constant value
  would merge "sustained at 0.305" and "extinguished at 0.275" into one point. The implied zero-flow point
  (~pot 0.14, fan ~3.9 V) is consistent with the calibration sheet's note that the fan stops above 3.8 V.
  (Superseded rule, 2026-11-15: "half of the lowest calibrated flow".)
- BASS (PSI-26, 2012–13) has no fan calibration in the integrated files: prefer air/cm·s values; fan/pot
  values convert with the BASS-II calibration under flag `calibration_borrowed_from_bass2`, confidence low.

## 4. Analysis coordinates, coverage and support

Coordinates used by models and coverage (per material family):
- `z_o2 = oxygen_percent` (mole/volume %)
- `z_flow = ln(1 + airflow_cm_s)`
- `z_p = ln(pressure_kpa / 101.325)`

Coverage reference scales (model-independent, documented): `s_o2 = 2.0`, `s_flow = 0.5`, `s_p = 0.1`.
Standardized distance `d(a,b) = sqrt(Σ ((a_i − b_i)/s_i)^2)`.
- Comparable observation: same `material_family` (and configuration when the analysis is configuration-
  specific) with `d ≤ 1`.
- Nearest-neighbour gap: `nn_d = min d` to that family's training observations; sparse if `nn_d > 1`.
- Hull support: inside the convex hull of observed points in the varying dimensions (degenerate
  dimensions such as pressure are checked separately with tolerance `1·s`).

Model support verdict at a query point (computed by the backend, thresholds documented in decisions.md):
`supported` | `extrapolation` | `insufficient_evidence`. UI text for the last one is exactly:
**"Insufficient experimental evidence for a reliable estimate."**

Baselines (`models/baselines.py`): majority class; L2 logistic on `z_o2` only; L2 logistic on
`[z_o2, z_flow, z_flow²]`; bootstrap ensemble of the latter (B=200) for an alternative uncertainty.
Metrics (`evaluation/metrics.py`): Brier, log loss (clip 1e-6), ROC-AUC, ECE (10 equal-width bins with
counts), reliability-diagram data, group-bootstrap CIs (resample experiments).
CV (`evaluation/cv.py`): grouped K-fold by `experiment_id`, leave-one-group-out by `campaign_group`,
leakage assertions; hyperparameters are refit inside each training fold only.

`{"error": {"code": "...", "message": "...", "details": {...}}}` with codes
`validation_error` (422), `not_found` (404), `artifact_missing` (503), `ingestion_failure` (500),

## 2.5 TM Appendix A evidence (BASS-II)

`data/curation/evidence/bass2_tm_appendix_a.csv` (columns `test_label,pi_sheet,configuration_label,observation_text,
printed_page,pdf_page,table,source_url,extraction_note`) holds the 126 as-run rows printed in NASA/TM-20210011385
Appendix A. Steps CSVs may carry three optional trailing columns `evidence_source,evidence_page,evidence_quote`
(a chunk may omit all three). Rules implemented in the pipeline:
- A step whose `raw_column` is exactly `TM Appendix A observation` is verified against the evidence CSV: `raw_token`
  must be a substring of that test's `observation_text` (same `pi_sheet` preferred), else `provenance_mismatch`
  (same rule as `scripts/check_curation_provenance.py`).
- Observations with a non-empty `evidence_source` get the quality flag `outcome_evidence_nasa_tm_20210011385`;
  `confidence` stays as written in the CSV.
- PSI-25 `ExperimentRecord.notes_raw` = the Appendix A `observation_text` verbatim (the PSI-25 workbook has no
  observation column), flag `notes_from_nasa_tm_20210011385`; `measurement_method` states the TM as the source.
- `dataset_report.json` key `evidence`: `steps_with_tm_evidence`, `tests_with_tm_evidence_steps`,
  `steps_with_tm_evidence_in_training`, `experiments_with_tm_notes`, `configuration_changes_vs_previous_labels`
  (diff against `data/normalized/experiments.json` as it was before this build), `context_records_by_source`.

## 2.6 Context tables (other apparatus or durations)

`data/curation/context_microgravity/<source_id>.csv`, UTF-8, header exactly
`context_id,investigation_short,investigation_name,platform,gravity_environment,years,material,specimen_geometry,
sample_dimensions,flame_configuration,oxygen_percent,total_pressure_kpa,total_pressure_raw,airflow_cm_s,airflow_raw,
outcome_text,source_title,source_url,ntrs_id,page,table,raw_text` (on one line). One row per printed test/sample
row; numbers as printed (conversions only into `*_kpa` / `*_cm_s`, printed value+unit kept in `*_raw`);
`outcome_text` verbatim and only when printed. A file with another header is skipped and reported in
`context_problems`. Each row becomes an `ExperimentRecord`:
- `experiment_id` = `<investigation_short>:<part of context_id after the first colon>`; `investigation_id` =
  `NTRS-<ntrs_id>` (one `Investigation` per NTRS document, role `integrated_context`, `landing_url` = the NTRS
  citation URL, license "NASA Technical Reports Server document; see source", `doi` null); `campaign_group` =
  `investigation_short`.
- Pressure only from the printed value (`total_pressure_kpa`), never assumed. `observed_outcome` only from the
  explicit words burns / extinguishes / extinguished / no ignition, else `unknown`.
- `material_family` / `specimen_geometry` only when determinable (else `other` / null); `extraction_method`
  `manually_transcribed`; `included_in_training` false, `exclusion_reason` "context only: different apparatus or
  test duration"; flag `context_record`; zero observations; `notes_raw` = `outcome_text | raw_text`.

`blindspots build-dataset` reads `BLINDSPOTS_NORMALIZED_OUT` as the output directory;
`python -m blindspots.pipeline.build_dataset --out DIR` does the same (default `data/normalized`).
